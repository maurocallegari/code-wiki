Il Metodo

Un contratto chiuso, una patch piccola, prove capaci di smentire il modello.

La formula universale

FILE: [path esatto o lista chiusa]
TASK: [un verbo + un risultato osservabile]
INPUT: [bug attuale + reference reale]
OUTPUT: [file e comportamento attesi]
VINCOLI: [cosa non toccare + convenzioni]
VERIFICA: [parser + diff + test browser/API]

Il ciclo in sette mosse

  1. Isola. Trova file, comportamento e confini.
  2. Fotografa il prima. Salva status, riproduzione e baseline.
  3. Dai un reference. Un file corretto vale più di “segui lo stile”.
  4. Fai una patch piccola. Un obiettivo, pochi file.
  5. Verifica staticamente. Sintassi, diff, pattern vietati.
  6. Verifica funzionalmente. Browser, API o flusso reale.
  7. Registra e deploya. Kanban, versione/cache, controllo live.
# WHY: separa modifiche preesistenti da quelle dell’agente.
git status --short

# WHY: il parser trova errori invisibili in una review veloce.
php -l view/agenti/agenti_lista.php

# WHY: controlla patch sporche e scope reale.
git diff --check
git diff --stat && git diff -- view/agenti/agenti_lista.php
Il terminale non basta“Nessun errore” non prova che il filtro mobile funzioni. Se il task riguarda un dito, devi toccare e scorrere il controllo su mobile.

Golden rules

  • Una sessione, un obiettivo.
  • Parti con 3 file omogenei; passa a 5–10 solo dopo una matrice tutta verde.
  • Mai fidarti del riepilogo: leggi git diff.
  • Non correggere una baseline che non hai riprodotto.
  • “Fatto” viene dopo test funzionale e, se previsto, smoke test live.

Il mio stile

Le 11 convenzioni STH Assitec. Sono istruzioni, non suggerimenti.

  1. Bootstrap PHP. Tre require_once nell’ordine esatto.
  2. Tabelle. plural_lowercase: studi, agenti, materiali.
  3. Primary key. ID, auto-increment.
  4. Relazioni. ID + tabella: IDStudio, IDTestata; niente FK fisiche.
  5. Flag. IS_*, valori 0/1.
  6. Computed. Tab_* aggiornati solo da trigger, mai dal PHP.
  7. Lookup e figli. tab_*; {parent}_righe, es. righe_intervento.
  8. Dominio. Non tradurre i termini italiani.
  9. CRUD. Usa $CRUD->Page() e $CRUD->Form() da un reference reale.
  10. Funzioni. Un solo array $params; prefissi approvati.
  11. Legacy protetto. Non modernizzare mysql_*; non toccare zone vietate.

Bootstrap e CRUD esatti

// WHY: configure.php definisce i path condivisi per primo.

Best Practices 2026

Meno tool, contesto più stretto, prove più forti. La baseline che puoi spiegare.

Instabile per naturaModelli, provider, flag e prezzi cambiano. Controlla documentazione e --help prima di cambiare configurazione: qui trovi criteri, non un “migliore per sempre”.
AreaScelta 2026Perché
IstruzioniAGENTS.md corto + skill dettagliateRegole vicine al codice
ModelloReasoning forte per diagnosi/review; coding agent per patchSepara decisione ed esecuzione
SandboxRead-only audit; workspace-write patchMinimo privilegio
ReteSpenta salvo necessitàMeno variabilità/esfiltrazione
Batch3, poi 5–10Limita fallimenti parziali
StatoGit + KanbanLa chat non è memoria
DeployManifest + rollback + smokeFTP “ok” non significa live

Come scegliere modello/provider

  1. Il modello più capace disponibile per capire STH, diagnosticare e revisionare rischio.
  2. Un agente coding con strumenti e sandbox per patch e batch.
  3. Reference preciso prima di contesto enorme.
  4. Benchmark personale: 5 task reali STH/Insta; misura scope, test, costo e tempo.
  5. Non cambiare provider nel mezzo di un batch.

Tooling minimo raccomandato

Git + rg + parser/linter + test applicativi
Codex CLI nel repository
Hermes per orchestrazione, Kanban, cron e deploy
AGENTS.md in ogni repo
Skills: sth-conventions · repo-import · verified-deploy · kanban-daily

Ho provato ad accumulare tool e skill: il router sceglieva quella quasi giusta invece di quella specifica. Archivia integrazioni inutilizzate e skill sovrapposte.

Sicurezza e supply chain

  • Pin di versioni e lockfile quando supportati.
  • Leggi gli script di installazione prima di eseguirli.
  • Segreti in secret store o .env ignorato.
  • Niente dump DB o log clienti nei prompt esterni.
  • Connector solo con i permessi necessari; conserva audit trail.
Regola delle tre chiaviUn agente con shell, rete e segreti è un amministratore. Non concedere tutte e tre se serve solo una patch locale.

Riesame ogni trimestre

  • Quali skill sono state davvero invocate?
  • Quali verifiche hanno trovato bug?
  • Quali cron hanno fallito silenziosamente?
  • Quale modello ha rispettato meglio i 5 benchmark?
  • Quali accessi non servono più?

Creare le tue skill

Trasforma un errore ricorrente in istruzioni verificabili, non in un prompt più arrabbiato.

Follow me: creiamo sth-conventions. Trigger: ogni modifica nel repo STH o un task che cita i suoi termini di dominio.

1. Un solo compito

Non mettere deploy, import e CRUD nella stessa skill. Ho provato skill enciclopediche: caricavano troppe regole e saltavano quelle decisive.

2. Raccogli prove reali

  • Una lista corretta con $CRUD->Page().
  • Un form corretto con $CRUD->Form().
  • Una funzione con $params.
  • Schema/trigger che gestisce un Tab_*.
  • Un esempio negativo incontrato davvero.
Pulisci gli esempiNon copiare password, DSN, dati cliente o contenuto di configure.php nei reference.

3. Crea la struttura

sth-conventions/
├── SKILL.md
└── references/
    ├── list-pattern.php
    ├── form-pattern.php
    └── verification.md

4. Scrivi SKILL.md

---
name: sth-conventions
description: Applica convenzioni STH a PHP/MySQL, CRUD, naming e dominio.
---

## Prima di modificare
1. Leggi AGENTS.md e il target completo.

Tutorial · Fix bug

Caso STH reale: filtro A–Z della lista agenti inutilizzabile su mobile.

1. Riproduci, non indovinare

cd /home/clawy/dev/sth-assitec-gpt
git status --short
# WHY: localizza il controllo reale; non presumere classe o markup.
rg -n "A-Z|alfabet|Left|agenti" view/agenti/agenti_lista.php

A 320, 375 e 414 px registra: esce dal viewport? Va a capo? I link sono troppo piccoli? Non scorre? La causa dipende da ciò che osservi.

2. Contratto per Codex

Read AGENTS.md and view/agenti/agenti_lista.php completely.
FILE: view/agenti/agenti_lista.php
TASK: make the existing A–Z filter usable by touch at 320–414 px.
INPUT: preserve all 26 links and their Active/Link/Label logic.
OUTPUT: one row, horizontal scroll on narrow screens; every letter clickable;
no page-level horizontal overflow.
CONSTRAINTS: only filter container/presentation. Do not change Table, Header,
Sidebar, PHP link logic, mysql_*, *_old/, action/crud/functions.php, app/, plugins/.
VERIFY: php -l; git diff --check; inspect diff; test 320/375/414 px.
Never claim a browser test you did not run.
Perché è precisoHo provato “sistema il mobile”: il modello ha ridisegnato la pagina. Qui comportamento, scope e viewport chiudono quella porta.

3. Pattern possibile, non soluzione cieca

/* WHY: lo scroll resta nel filtro e non allarga la pagina. */
.agents-alpha-filter { display:flex; gap:.5rem; overflow-x:auto;
  overscroll-behavior-inline:contain; -webkit-overflow-scrolling:touch; }
/* WHY: ogni lettera resta un target touch singolo. */
.agents-alpha-filter a { flex:0 0 auto; min-width:2.75rem; min-height:2.75rem; }

4. Smentisci “done”

php -l view/agenti/agenti_lista.php
git diff --stat
git diff -- view/agenti/agenti_lista.php
git diff --check
rg -n "overflow-x|overflow-inline|-webkit-overflow-scrolling" view/agenti/agenti_lista.php
  • Nessuno scroll orizzontale pagina.
  • Swipe filtro a 320/375/414 px.
  • A e Z raggiungibili.
  • Ogni lettera filtra come prima.
  • Desktop invariato.

Metti la card in Verifica. Dopo deploy ripeti live e controlla cache/versione; solo allora Fatto.

Sequenza verificata

  1. Salva checksum/mtime remoto o copia rollback fuori webroot.
  2. Carica con nome temporaneo nella stessa directory, se supportato.
  3. File 0644, directory 0755, segreti 0600.
  4. Rinomina atomica o upload esplicito dal manifest.
  5. Bump versione/cache secondo il progetto reale.
  6. Verifica HTTP, marker/contenuto e flusso funzionale.
  7. Conserva rollback fino allo smoke test concluso.

Problemi comuni

Dieci errori già abbastanza costosi da diventare regole.

01

“Ha detto fatto”

La patch è finita, non il test. Chiedi comandi, output e live. Se il browser non è stato aperto: “non verificato”.

02

File fuori scope

Lista chiusa + git diff --name-only. Non fare checkout cieco: potresti cancellare lavoro tuo.

03

Vincoli dimenticati

AGENTS.md + skill + vincoli ripetuti. Per T2, reference reale obbligatorio.

04

Batch enorme

Tre file omogenei, matrice, stop al primo errore. Solo poi 5–10.

05

STH “modernizzato”

Scrivi che mysql_* è shim. Niente FK fisiche; Tab_* non si salva dal PHP.

06

Venti tentativi senza diagnosi

Audit read-only, baseline, un’ipotesi. Dopo tre fallimenti torna ai dati e riduci.

07

Mobile “responsive”, ma intoccabile

320/375/414 px, target ~44×44, scroll interno e prova su iPhone.

08

FTP ok, live vecchio

Manifest, marker/checksum, bump versione, curl e flusso funzionale.

Disco claw.nswr.it pieno
